# Actual app lip dictation proof

Run only on a fresh, disposable GitHub-hosted ARM64 macOS runner. The script refuses local Macs, root execution, a different desktop owner, or a mismatched declared app build head. It grants test permissions to the exact signed app and helper requirements on that disposable host. It does not change SIP, Gatekeeper, system-extension policy, credentials, or product code.

Before building the app or downloading models, compile, link, sign, and load the native visual helper:

```sh
python3 Tools/LipDictationE2E/run.py --build-helper-only
```

This command needs no app, model, OBS, or permission grants. It compiles the actual existing runtime helper sources and the visual entry point, verifies the signed bundle, and requires a positive native load acknowledgment. It writes `nativeHelperBuilt` on success. This establishes helper build/load evidence only. Normal voice and visual execution perform the same check before any app/model/OBS work.

Run the positive-observation regression before a full build:

```sh

```

It restores plain AX reads in place of the two live association checks and removes the positive sample's display/reference mismatch discard. Baseline ownership, baseline pixel comparison, both captures and frame storage remain. Both helpers must accept healthy text and the transparent panel with matching captured pixels. Only readable covered/moved false acceptance qualifies as the expected red result. The bad opaque-cover receipt must retain a factually mismatching display/reference pair. Permission, compile, timeout, cleanup, or unrelated errors fail the gate. The tracked source is restored and hashed in `finally`. The bad helper uses the exact separate identifier `com.negentropi.LipDictationE2E.AssociationKnownBad`, its own signed requirement and a separate normal screen-capture Allow receipt. Candidate permission and capture are established independently afterward. No permission receipt transfers between builds.

Before model downloads or dictation fixtures, both signed helpers perform a real ScreenCaptureKit capture through the existing rendered-text capture session. The expected sentence enters only the observer, never the app or recognition model.

The visual helper compiles the existing runtime helper sources with one extra entry point. No app-specific fake camera input, recognition result, or insertion hook is introduced. The default full sequence installs the model through the actual settings UI before provisioning OBS. The Setup UI and model installation run separately from camera-device provisioning. The source movie keeps the existing 640×480, 25 fps conversion, one-second cloned-face lead and half-second tail. Enqueue receipts establish source submission, not every image received by the app, physical-webcam behavior, broad recognition accuracy, or product latency. The actual app's capture, recognition, insertion, history and cleanup checks remain separate gates.

The source stays alive until the matching app capture closes, or the owned app exits for quit.
