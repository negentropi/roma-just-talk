# macOS draft-release publication

The official publication workflow accepts an existing stable draft and a completed distribution qualification run. It verifies the app before attaching the informational Sparkle feed or publishing the draft. It does not create releases, tags, signing certificates, or qualification evidence.

Publication is currently blocked. The shared qualification verifier rejects unestablished controller origin. Developer ID signing, the qualification producer, both exact normal first-Open rows, and a valid automatic controller export remain prerequisites. A successful ad-hoc launch or source build cannot satisfy them.

## Inputs and trust

`.github/workflows/publish-update-feed.yml` runs only through an explicit default-branch `workflow_dispatch`. It checks out the dispatch commit and checks its exact identity. It accepts these inputs:

- `release_id`: the existing unpublished stable draft.
- `application_sha`: the exact application commit, also identified by the release tag.
- `qualification_run_id` and `qualification_run_attempt`: the completed successful producer attempt.

The reviewed dispatch commit supplies the expected qualification tooling SHA. The repository variable `MACOS_DEVELOPER_ID_TEAM` supplies the expected ten-character signing team. Missing policy inputs fail. The downloaded evidence cannot choose either value.

The consumer requires `.github/workflows/qualify-macos-distribution.yml` in `negentropi/roma-just-talk`. It reads authenticated API metadata, downloads the qualification and source artifacts, and invokes `verify-macos-release-qualification.py` in live mode. Uploaded pass flags and offline metadata cannot authorize writes. The [shared qualification contract](macos-release-qualification.md) defines the required rows and raw proof.

The draft permits one `roma.just.talk.app.zip` and an optional identical `appcast.xml`. Additional assets, duplicate names, incomplete uploads, expired artifacts, and truncated API inventories fail. GitHub's automatically generated source archives are outside this app distribution contract.

## Byte and release binding

The consumer peels annotated tags to the underlying commit. `target_commitish` does not establish tag identity. The final app's bundle identifier, short version, and build number must match the intended release. Its verified plist supplies the appcast's minimum OS.

The consumer downloads the draft app asset by ID and recomputes its SHA-256 and size. Both must match the qualified direct ZIP. It reads the draft again and repeats the download immediately before publication. A changed asset ID, digest, tag, release notes, or name blocks publication.

The appcast keeps the existing release-page link, version mapping, XML escaping, and absence of a Sparkle enclosure. Its timestamp is an explicit UTC publication intent chosen before publication. A retry retains the timestamp from an existing appcast and regenerates every other field from the verified app and unchanged draft. An existing appcast must match regenerated bytes exactly. The consumer never uses `--clobber`.

Workflow concurrency serializes publication by release ID. After every predicate passes, the consumer attaches the appcast while the release remains draft, rechecks both assets, and publishes by release ID. It verifies the public release state and downloads the same asset IDs again. A failed postpublication check reports failure; it does not delete or silently replace public assets.

## CLI

The default CLI mode verifies a draft without writing to GitHub. `--publish` enables attachment and publication only after successful qualification. Use a new output directory for every invocation. Existing directories remain untouched.

```sh
python3 scripts/publish-qualified-macos-release.py "$RELEASE_ID" \
	--qualification-run-id "$QUALIFICATION_RUN_ID" \
	--qualification-run-attempt "$QUALIFICATION_RUN_ATTEMPT" \
	--expected-source-sha "$APPLICATION_SHA" \
	--expected-tooling-sha "$REVIEWED_TOOLING_SHA" \
	--developer-id-team "$DEVELOPER_ID_TEAM" \
	--output-dir "$NEW_OUTPUT_DIRECTORY"
```

Current evidence returns `state=blocked`, exit status 1, and zero publication writes. The output directory retains `publication-result.json` and, when reached, the actual shared verifier's `qualification-result.json`. Failed downloads and extracted evidence remain available locally. The workflow retains only these result files as its publication artifact.

## Verification and limits

```sh
python3 scripts/tests/macos-release-publication.test.py
python3 scripts/tests/macos-release-qualification.test.py
node --test scripts/tests/github-release-appcast.test.js
```

The publication tests execute the old workflow's actual upload block through a controlled `gh` subprocess transport. The old route uploads an informational feed for an unqualified archive. The new consumer runs the actual qualification CLI on recorded ad-hoc failure fields and performs zero writes. Other tests exercise asset download bytes, replacement between checks, tag peeling, metadata drift, immutable appcast retries, actual plist version checks, and the default-branch dispatch guard.

Transport fixtures and version-only ZIPs establish consumer behavior. They do not establish authenticated GitHub execution, signed first Open, or successful publication. There is no signed or controller-positive fixture. No test writes to real GitHub.

Direct administrator publication, other external publishers, and writers who can replace trusted workflow code remain outside this boundary. Concurrent external draft edits can race the final API operation. Repository permissions and immutable releases require separate verified controls. This workflow protects its supported publication route; it does not claim to prevent every administrator bypass.
